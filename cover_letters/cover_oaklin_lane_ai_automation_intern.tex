\lettercontent{Dear Chris Callander,}

\lettercontent{I am applying for the AI \& Automation Intern role at Oaklin Lane. I build small systems that take repetitive work off people's plates: a TypeScript Discord bot that respects a tight API quota, and a Claude Code workflow that turns job search admin into a repeatable process. I want to put that same practical approach on clinic operations as you grow neighborhood sites beyond Rockwall and Lake Highlands.}

\lettercontent{Oaklin Lane's stated problem is access. Families wait too long for speech, occupational, physical, and feeding therapy, and they should not have to coordinate three clinics to get one plan. You put those specialties under one roof. That only scales if intake, authorizations, reporting, recruiting, and family communication stop living in one-off spreadsheets. That is the work I want: find the slow step, prototype a tool, measure whether it actually saved time.}

\lettercontent{What I would bring in the first months:}

{\raggedright\fontspec[Path = OpenFonts/fonts/raleway/]{Raleway-Medium}\fontsize{11pt}{13pt}\selectfont
\begin{itemize}
    \item \textbf{Prototype, then prove it:} I would start with one painful loop (a recurring ops report, a recruiting screen, or an internal FAQ) and ship a Claude- or API-backed draft the team can reject or keep.
    \item \textbf{Constraint-aware automation:} My CS2 Discord bot calls GGScore only on an explicit sync, then serves slash commands and reminders from SQLite so a 3-request/day limit is not burned. I would treat vendor cost, rate limits, and PHI risk the same way.
    \item \textbf{Docs that other people can run:} The bot ships with a setup guide and a free-tier usage plan. I would write the same kind of instructions for any tool we ask clinicians or coordinators to touch.
\end{itemize}\par}
